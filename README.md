# 时间日记的活动替代分析与学习参与情景解释

这是一个面向社区老年教育运营的本地分析原型，使用合成记录演示从业务记录到运营摘要的处理。项目把记录读取、统计口径和运营判断分开，便于核对原始事实与派生结果。

## 环境与使用

需要 Python 3.11 或更高版本，无第三方依赖。

- 运行测试：`python3 -m unittest discover -s tests -v`
- 查看分析报告：`python3 -m learning_time_use.report`
- 重新生成合成日记（固定随机种子，结果可复现）：`python3 scripts/make_synthetic_diaries.py`

所有记录均为本地合成数据，不包含个人信息。SQLite 数据库在调用时创建于临时目录，原始 CSV 保持不变。
也可使用 Docker 运行：`docker build -t learning-time-use .`，再执行 `docker run --rm learning-time-use`。容器内运行测试可执行 `docker run --rm --entrypoint python3 learning-time-use -m unittest discover -s tests -v`。

## 分析问题

“增加两小时学习会挤掉什么”不能靠把学习、照护、家务、休闲各自求平均再分别与满意度相关来回答——一天的总时长不会变长，活动之间是替代关系。本项目在原有汇总之外，增加了受约束的情景比较：例如**从可自行安排的休闲中转出 60 或 120 分钟给学习**，而不是削减不可转移的照护责任。

## 口径约定（与结论可信度直接相关）

1. **只在完整日记上做日内替代。** 日记可能只覆盖部分时段；部分日与整日缺失保留在审计清单中，绝不按回收比例补齐或缩放后当作真实安排。
2. **主活动与伴随活动是两本账。** 主活动分钟互斥、合计为一天时长；伴随活动是可与主活动重叠的暴露时长，单独汇总，两者不混算。
3. **零分钟与未记录严格区分。** 完整日中确实没做的活动登记在 `zero_activities`；伴随活动留空表示未记录，与显式 0 分钟不是同一口径，读取与核算层均有校验。
4. **工作日与周末全程分列。** 回收比例不同的两个口径不混合平均、不跨口径匹配共同支持。
5. **谁能共同支持结论有明确资格线。** 必须两波同一口径都有完整日记、且两波满意度随访齐全，才进入个体内变化模型；其余人员进入选择诊断与审计，不静默丢弃。

## 模块分工

| 模块 | 职责 |
| --- | --- |
| `diary_io.py` | 日记日、时段、随访、名册的读取与字段校验（时段重叠、伴随时长越界、零/缺失区分） |
| `accounts.py` | 逐日时间账、覆盖审计、原始时间账（不补齐）、完整日人员向量 |
| `cohort.py` | 模型队列资格、随访链接、选择性缺失诊断（SMD、覆盖率-满意度相关、流失基线差） |
| `regression.py` | 纯标准库 OLS 与个体内差值替代关联，输出系数、标准误与 95% 置信区间 |
| `scenarios.py` | 情景硬约束（不负时间、总时长不变、保护照护）、共同支持匹配与推荐分级 |
| `audit.py` | 导出原始时间账与情景审计 CSV，列明用了哪些日子、舍弃了哪些资料及原因 |
| `pipeline.py` | 串联上述步骤，可指定 `audit_dir` 落盘审计文件 |
| `records.py` / `analysis.py` / `operations.py` / `storage.py` | 既有合成汇总链路，原样保留 |

## 情景规则与结论分级

- **硬约束**：来源活动余额不足即判不可行；任何活动不得为负；转出多少就转入学习多少，一天总时长不变；受保护活动（照护、其他刚性时间）不能作为来源。
- **共同支持**：情景后的活动向量必须在同口径真实完整日的邻域内（学习量与来源余额两维匹配，至少 3 个相邻观察日）。没有类似时间组合的人只给方向性说明，**不做精确改善承诺**。
- **选择性缺失参与推荐决策**：当日记缺失、活动构成与满意度变化相互关联（SMD、覆盖率相关、流失基线差触发阈值），情景整体降级为“谨慎参考”，而不是只附一句免责声明。
- **观察关联而非因果**：关联模型为个体内两波差值回归，仅控制不随时间变化的个体差异；报告与审计输出均标注“观察关联，非因果效果”。
- **不确定性与适用范围**：满意度预测给 95% 区间而非点承诺，并限定在共同支持覆盖的人群内；样本不足或设计矩阵奇异时明确返回“无法估计”。

## 审计与复核

`run_pipeline(audit_dir=...)` 会写出两份清单：

- `time_ledger.csv`：每个日记日的覆盖状态、主活动分钟、伴随暴露与未记录分钟，按原记录保留；
- `scenario_audit.csv`：每人每情景的基线日、情景前后向量、可行性、共同支持匹配日编号。

当前摘要只反映样例记录的演示结果，不用于形成个体资格或运营承诺。
